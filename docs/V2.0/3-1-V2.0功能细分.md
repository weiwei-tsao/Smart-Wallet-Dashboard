## 1. 前端（Next.js + React）

这个模块的重点在于利用 **Next.js** 提升应用的性能和 SEO。

- **项目迁移与路由**
  - **从 Vite 迁移到 Next.js**：除了基本的组件迁移，你还需要配置 `_app.js` 和 `_document.js` 来管理全局状态（如 Redux）和自定义 HTML 结构。
  - **动态路由**：创建 `/pages/address/[id].js` 文件，使用 `useRouter` 钩子获取地址参数 `id`。
- **SSR/ISR 渲染**
  - **SSR（服务器端渲染）**：在 `/pages/address/[id].js` 中，使用 `getServerSideProps` 函数在服务器端获取钱包余额和交易列表。这能确保每次请求都得到最新的数据，非常适合展示实时性要求高的信息。
  - **ISR（增量静态生成）**：使用 `getStaticProps` 和 `revalidate` 参数实现。例如，设置 `revalidate: 60` 表示页面每 60 秒重新生成一次。这适合数据更新不那么频繁但需要良好性能的页面，可以减轻服务器压力。
  - **README 对比**：在 README 中，用表格或简短的文字对比 SSR 和 ISR 的优缺点、适用场景（如：**SSR 适用于实时数据，ISR 适用于高流量、数据不需秒级更新的页面**），并说明你在项目中选择它们的理由。
- **技术栈整合**
  - **状态管理**：确保 Redux Toolkit 能在 Next.js 的 SSR 环境下正常工作，你可能需要使用 `next-redux-wrapper` 或类似方案。
  - **数据获取**：Apollo Client 可以继续用于获取图数据，但对于 RESTful API，直接在 `getServerSideProps` 或 `getStaticProps` 中使用 `fetch` 或 `axios` 会更直接。

## 2. 后端（Node/Express BFF）

BFF（Backend For Frontend）层的核心价值在于统一数据接口、减轻前端负担并实现数据缓存。

- **REST API 接口设计**
  - **交易数据**：`GET /api/txs?address=0x...`。这里建议将 `tx` 改为更清晰的 `txs`（多条交易）。接口返回的数据应是经过处理和精简的，只包含前端所需字段。
  - **Token 列表**：`GET /api/tokens?address=0x...`。同样，返回处理后的 Token 数据，如余额、名称、符号、合约地址等。
  - **收藏地址**：
    - `POST /api/favorites`：请求体包含 `address` 和 `alias`，用于新增收藏。
    - `GET /api/favorites`：返回用户收藏的所有地址列表。
    - `DELETE /api/favorites/:id`：可选，用于删除特定收藏。
- **缓存与数据库**
  - **Redis 缓存**：在 BFF 层接收到请求后，首先检查 Redis 是否存在缓存。如果存在且未过期，直接返回缓存数据；否则，调用外部 API（如 Etherscan），将结果存入 Redis 并设置过期时间（TTL），然后返回给前端。
  - **PostgreSQL 存储**：设计一个 `favorites` 表，包含 `id`、`address` 和 `alias` 字段。使用 ORM（如 Sequelize 或 Prisma）简化数据库操作。

## 3. 基础设施（Docker & CI/CD）

这部分展示了你对现代软件开发流程的理解。

- **Docker Compose 容器化**
  - 在 `docker-compose.yml` 文件中，定义 `web`（Next.js）、`bff`（Node/Express）、`redis` 和 `postgres` 四个服务。
  - 配置好各自的端口映射、卷（volumes）和环境变量。`bff` 服务需要连接 `redis` 和 `postgres`，确保网络设置正确。
  - 提供清晰的命令说明，如 `docker-compose up -d`，让面试官或协作者能一键启动整个项目。
- **GitHub Actions CI/CD**
  - 创建 `.github/workflows/ci.yml` 文件。
  - **CI 流程**：
    - `on: [pull_request, push]`：配置触发条件。
    - `jobs`：定义一个 `build` 或 `test` job。
    - `steps`：
      1.  `actions/checkout`：检出代码。
      2.  `actions/setup-node`：安装 Node.js。
      3.  `npm ci`：安装依赖，使用 `ci` 命令以保证版本一致。
      4.  `npm run lint`：代码风格检查。
      5.  `npm run type-check`：TypeScript 类型检查。
      6.  `npm test`：运行单元测试。
      7.  `npm run build`：构建生产版本。
  - **可选部署**：添加一个部署步骤，当代码合并到 `main` 分支时，自动将 `web` 和 `bff` 部署到云服务（如 Vercel 或 Render）。

## 4. Web3 功能扩展

这是项目最核心、最具亮点的部分。

- **Ethers.js 合约交互**
  - **ABI 与合约实例**：使用 ERC-20 的标准 ABI，通过 `Ethers.js` 创建合约实例 `new ethers.Contract(address, abi, provider)`。
  - **方法调用**：调用实例的 `totalSupply()` 和 `decimals()` 方法。
  - **数据展示**：将获取的元信息（如总供应量）格式化后在前端展示。
- **测试网 Demo**
  - **选择测试网**：Goerli 或 Sepolia 都可以，两者都是主流测试网。
  - **实现功能**：
    - **读取余额**：调用 `provider.getBalance(address)`。
    - **最小交易**：创建一个 **只读** 的 Demo 区块，展示如何构造一个最小的 `transfer` 或 `mint` 交易。但为了安全，实际的签名和发送操作可以不实现，或者只在本地开发时展示。
- **前端亮点**
  - 在 Dashboard 上创建一个独立的卡片或区块，命名为 "**合约元信息**" 或 "**合约交互演示**"，展示 ERC-20 合约的总供应量和精度，并提供一个输入框，让用户可以输入 Token 合约地址来查询。
