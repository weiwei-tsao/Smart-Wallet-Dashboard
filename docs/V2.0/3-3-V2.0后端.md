很好，接下来我们深入细化后端（BFF）服务的设计。

## 2. 后端（Node/Express BFF + TypeScript）

这个 **BFF (Backend for Frontend)** 层是整个项目的枢纽，它的主要作用是整合来自不同数据源（链上 API、数据库）的数据，并以统一、高效的格式提供给前端。这不仅能简化前端的数据请求逻辑，还能集中管理缓存和业务逻辑，从而提升性能。

### **2.1 REST API 接口设计**

我们将为每个主要功能设计清晰、符合 RESTful 规范的 API 路由。

- **交易数据接口**

  - **路由**：`GET /api/txs?address=<wallet_address>&chainid=<chain_id>`
  - **参数**：
    - `address` (必需)：要查询的钱包地址。
    - `chainid` (可选)：区块链网络 ID，默认为 1 (Ethereum Mainnet)。
    - `page` (可选)：分页页码，例如 `page=1`。
    - `limit` (可选)：每页条目数，例如 `limit=20`。
  - **功能**：这个接口是 BFF 的核心。它会调用 **Etherscan V2 API** 来获取一个地址的交易列表。为了减少前端的请求负担，BFF 在这里会进行一次**数据精简和格式化**。它只会返回前端需要的关键信息，例如：`hash`, `from`, `to`, `value`, `timestamp`, `blockNumber`。
  - **Etherscan V2 API 集成**：
    - 使用新的 V2 端点：`https://api.etherscan.io/v2/api?chainid=${chainid}`
    - 支持多链查询（Ethereum, Polygon, BSC, Arbitrum, Optimism 等）
    - 自动处理 API 限流和错误重试
  - **缓存策略**：集成 Redis 缓存，减少对外部 API 的重复请求，缓存时间 60 秒。

- **ERC-20 Token 列表接口**

  - **路由**：`GET /api/tokens?address=<wallet_address>&chainid=<chain_id>`
  - **参数**：
    - `address` (必需)：要查询的钱包地址。
    - `chainid` (可选)：区块链网络 ID，默认为 1。
  - **功能**：调用 **Etherscan V2 API** 获取某个地址所持有的所有 ERC-20 Token 列表。BFF 层会处理好每个 Token 的名称、符号、合约地址、余额和价格信息，然后以简洁的 JSON 格式返回。
  - **多链支持**：通过 `chainid` 参数支持不同区块链网络的代币查询。

- **收藏地址 CRUD 接口**

  - **功能**：这些接口将与 PostgreSQL 数据库交互，用于存储和管理用户的收藏地址。
  - **新增收藏**：`POST /api/favorites`
    - **请求体**：`{ "address": "0x...", "alias": "My Main Wallet" }`
    - **返回**：新增的收藏地址对象。
  - **获取收藏列表**：`GET /api/favorites`
    - **功能**：返回用户所有收藏地址的列表。
  - **删除收藏**：`DELETE /api/favorites/:id`
    - **参数**：`id` (必需)：数据库中收藏地址的 ID。
    - **返回**：操作成功或失败的提示。

- **健康检查接口**
  - **路由**：`GET /health`
  - **功能**：检查服务状态，包括数据库连接、Redis 连接和外部 API 可用性。
  - **返回**：服务状态和各个组件的健康状态。

### **2.2 技术栈与实现细节**

- **Node.js 框架**：使用 **Express.js** 框架来快速搭建 RESTful API。
- **TypeScript 支持**：

  - 使用 TypeScript 进行类型安全的开发
  - 配置 `tsconfig.json` 进行严格的类型检查
  - 使用 `tsx` 进行开发时的热重载
  - 构建时编译为 JavaScript 以提升运行时性能

- **缓存层 (Redis)**：

  - **集成**：使用 `redis` 客户端库进行 Redis 连接和操作。
  - **连接配置**：通过环境变量 `REDIS_URL` 配置 Redis 连接。
  - **缓存策略**：在处理 `/api/txs` 和 `/api/tokens` 请求时，首先检查 Redis 缓存中是否有该地址的数据。
  - **键名规范**：使用清晰的键名，例如 `cache:txs:<address>:<chainid>` 或 `cache:tokens:<address>:<chainid>`。
  - **过期时间 (TTL)**：设置 60 秒的过期时间。这既能保证数据的相对新鲜度，又能显著降低对外部 API 的请求频率。
  - **错误处理**：Redis 连接失败时优雅降级，直接调用外部 API。

- **数据存储 (PostgreSQL)**：

  - **集成**：使用 **Prisma** ORM 工具来连接和操作 PostgreSQL 数据库。
  - **连接配置**：通过环境变量 `DATABASE_URL` 配置数据库连接。
  - **表结构**：设计一个 `favorites` 表，包含以下字段：
    - `id` (主键, CUID)
    - `address` (字符串, 唯一索引, 钱包地址)
    - `alias` (字符串, 昵称)
    - `createdAt` (时间戳)
    - `updatedAt` (时间戳)
  - **数据库迁移**：使用 Prisma Migrate 管理数据库 schema 变更。

- **外部 API 集成**：

  - **Etherscan V2 API**：
    - 使用 `axios` 进行 HTTP 请求
    - 支持多链查询（通过 `chainid` 参数）
    - 实现请求限流和错误重试机制
    - 环境变量配置：`ETHERSCAN_API_KEY`, `ETHERSCAN_BASE_URL`
  - **错误处理**：统一的错误处理中间件，返回标准化的错误响应。

- **安全与性能**：

  - **CORS 配置**：允许前端域名的跨域请求
  - **请求限流**：使用 `express-rate-limit` 防止 API 滥用
  - **安全头**：使用 `helmet` 设置安全相关的 HTTP 头
  - **压缩**：使用 `compression` 中间件压缩响应数据
  - **日志记录**：使用 `morgan` 记录 HTTP 请求日志

- **代码组织**：

  - 遵循分层架构原则，将代码组织为：
    - `routes/` - API 路由定义
    - `controllers/` - 请求处理逻辑
    - `services/` - 业务逻辑和外部服务集成
    - `middleware/` - 中间件（错误处理、验证等）
    - `types/` - TypeScript 类型定义
    - `config/` - 配置文件
  - 使用依赖注入模式，便于测试和维护

- **开发与部署**：
  - **开发环境**：使用 `tsx watch` 进行热重载开发
  - **生产环境**：编译 TypeScript 为 JavaScript，使用 `node` 运行
  - **Docker 支持**：提供 Dockerfile 和 docker-compose 配置
  - **健康检查**：内置健康检查端点，支持容器编排

---

BFF 层的核心在于其**数据聚合和缓存**能力，它将作为前端和复杂数据源之间的坚固屏障。通过 TypeScript 的类型安全和现代化的开发工具链，确保代码质量和可维护性。
