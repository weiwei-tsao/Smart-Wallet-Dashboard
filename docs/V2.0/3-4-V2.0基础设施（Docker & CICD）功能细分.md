## 3. 基础设施（Docker & CI/CD）

### 3.1 Docker & Docker Compose

我们将使用 **Docker Compose** 来定义和运行整个应用栈。它允许你用一个简单的配置文件启动所有服务，包括前端、后端、缓存和数据库，从而保证开发环境的一致性和可移植性。

- **`docker-compose.yml` 文件**

  - 在项目根目录下创建这个文件。它将定义四个核心服务：`web`、`bff`、`redis` 和 `postgres`。
  - **`web` 服务 (Next.js + TypeScript)**：
    - 使用轻量级的 Node.js 18 Alpine 镜像 `node:18-alpine`。
    - 在 `Dockerfile` 中，安装依赖、构建 TypeScript 项目，并以 `CMD ["npm", "start"]` 运行生产服务器。
    - **端口映射**：将容器的 3000 端口映射到宿主机的 3000 端口，让你可以通过 `http://localhost:3000` 访问前端。
    - **环境变量**：配置 `NEXT_PUBLIC_API_BASE_URL` 指向 BFF 服务。
    - **健康检查**：内置健康检查确保服务正常运行。
  - **`bff` 服务 (Node/Express + TypeScript)**：
    - 使用与 `web` 服务相同的 Node.js 18 Alpine 镜像。
    - 在 `Dockerfile` 中，安装依赖、生成 Prisma 客户端、构建 TypeScript 项目，并用 `CMD ["npm", "start"]` 运行 Express 服务。
    - **端口映射**：将容器的 3001 端口映射到宿主机的 3001 端口。
    - **环境变量**：
      - `DATABASE_URL`：PostgreSQL 连接字符串
      - `REDIS_URL`：Redis 连接字符串
      - `ETHERSCAN_API_KEY`：Etherscan API 密钥
      - `ETHERSCAN_BASE_URL`：Etherscan V2 API 基础 URL (`https://api.etherscan.io/v2/api`)
      - `CORS_ORIGIN`：允许的跨域来源
    - **健康检查**：内置健康检查端点确保服务正常运行。
  - **`redis` 服务**：
    - 使用官方的 `redis:7-alpine` 镜像。
    - **端口映射**：将容器的 6379 端口映射到宿主机的 6379 端口。
    - **数据持久化**：使用命名卷 `redis_data` 持久化数据。
    - **健康检查**：使用 `redis-cli ping` 检查服务状态。
  - **`postgres` 服务**：
    - 使用官方的 `postgres:15-alpine` 镜像。
    - **环境变量**：
      - `POSTGRES_DB=smart_wallet_dashboard`
      - `POSTGRES_USER=username`
      - `POSTGRES_PASSWORD=password`
    - **端口映射**：将容器的 5432 端口映射到宿主机的 5432 端口。
    - **数据持久化**：使用命名卷 `postgres_data` 持久化数据。
    - **健康检查**：使用 `pg_isready` 检查数据库连接状态。

- **网络配置**

  - 所有服务运行在自定义的 `smart-wallet-network` 桥接网络中。
  - 服务间可以通过服务名进行内部通信（如 `bff` 服务通过 `postgres:5432` 访问数据库）。

- **数据持久化**

  - 使用 Docker 命名卷确保 PostgreSQL 和 Redis 数据在容器重启后不丢失。
  - 卷配置：
    - `postgres_data`：存储 PostgreSQL 数据
    - `redis_data`：存储 Redis 数据

- **README 指南**
  - 在项目的 `README.md` 中，提供清晰的**一键启动**命令：`docker-compose up --build`。
  - 解释每个服务的用途以及如何访问它们：
    - 前端：`http://localhost:3000`
    - 后端 API：`http://localhost:3001/api`
    - PostgreSQL：`localhost:5432`
    - Redis：`localhost:6379`

### 3.2 GitHub Actions CI/CD

**持续集成（CI）** 流程确保每次代码提交或拉取请求（PR）都经过自动化测试和检查，从而在早期发现问题。

- **`.github/workflows/ci.yml` 配置文件**

  - 创建此 YAML 文件来定义 CI 流程。
  - **触发条件**：将工作流配置为在每次 `push` 到 `main` 分支或创建 `pull request` 时自动运行。
  - **CI 步骤**：
    1.  **环境设置**：使用 Node.js 18 和 Docker 环境。
    2.  **前端检查**：
    - 安装依赖：`npm ci`
    - Linting：`npm run lint`
    - Type-checking：`npm run type-check`
    - Build：`npm run build`
    3.  **后端检查**：
    - 进入 backend 目录
    - 安装依赖：`npm ci`
    - Linting：`npm run lint`
    - Type-checking：`npm run type-check`
    - Build：`npm run build`
    4.  **Docker 构建测试**：
    - 构建前端 Docker 镜像
    - 构建后端 Docker 镜像
    - 验证镜像可以正常启动
    5.  **数据库迁移测试**：
    - 启动 PostgreSQL 和 Redis 服务
    - 运行 Prisma 迁移
    - 验证数据库连接

- **Docker 集成测试**

  - **多阶段构建**：验证 Dockerfile 的多阶段构建过程。
  - **服务健康检查**：确保所有容器服务都能正常启动并通过健康检查。
  - **网络连通性**：验证服务间的网络通信（前端 ↔ 后端 ↔ 数据库）。

- **可选的持续部署（CD）**

  - **自动部署**：可以为 GitHub Actions 添加一个部署步骤，当代码成功合并到 `main` 分支后，自动将整个应用栈部署到云服务商。
  - **部署选项**：
    - **Docker Compose 部署**：在云服务器上使用 `docker-compose up -d` 部署整个应用栈。
    - **容器编排**：使用 Kubernetes 或 Docker Swarm 进行生产环境部署。
    - **云服务集成**：集成 AWS ECS、Google Cloud Run 或 Azure Container Instances。

- **环境变量管理**

  - 使用 GitHub Secrets 管理敏感信息（API 密钥、数据库密码等）。
  - 为不同环境（开发、测试、生产）配置不同的环境变量。

- **监控和日志**
  - 集成日志收集服务（如 ELK Stack、Fluentd）。
  - 设置监控告警（如 Prometheus + Grafana）。
  - 配置健康检查端点监控。

通过以上细化，你不仅能搭建一个功能完整的项目，更能展示你对现代 DevOps 实践和容器化部署的全面理解。
