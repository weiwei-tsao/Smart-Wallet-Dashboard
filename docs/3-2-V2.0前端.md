### **1.1 项目迁移与路由**

#### 从 Vite 迁移到 Next.js

这个过程不只是简单的文件复制，更重要的是理解 Next.js 的文件系统路由和页面生命周期。

- **文件结构**：将 `src` 目录下的 React 组件、hooks 和样式文件移动到 Next.js 的项目结构中。核心页面组件（如 Dashboard）应放在 `pages/` 目录下。
- **`_app.js`**：这是你项目的入口文件，用于初始化页面。在这个文件中，你可以集成 Redux store、Apollo Client、全局样式（如 Tailwind）和全局布局。它就像是 Vite 项目中的 `main.jsx`。
- **`_document.js`**：这个文件用于自定义 HTML 文档结构，比如添加自定义的 `<head>` 或 `<body>` 标签。对于这个项目，你可以用它来插入额外的 `meta` 标签或 Google Fonts。

#### 动态路由

Next.js 的动态路由非常直观，它将文件系统和路由路径绑定在一起。

- **创建文件**：在 `pages/address/` 目录下创建一个名为 `[id].js` 的文件。方括号 `[]` 告诉 Next.js 这是一个动态参数。
- **获取参数**：在 `[id].js` 页面组件中，你可以使用 `next/router` 的 `useRouter` 钩子来访问路由参数。

  ```javascript
  import { useRouter } from 'next/router';

  function AddressPage() {
    const router = useRouter();
    const { id } = router.query; // id 就是 URL 中的地址参数
    // ... 在这里使用 id 获取数据
    return <div>Address: {id}</div>;
  }
  ```

### **1.2 SSR/ISR 渲染**

#### SSR（服务器端渲染）

对于需要最新链上数据的钱包 Dashboard，**SSR** 是一个理想的选择。

- **函数**：在 `pages/address/[id].js` 页面中导出 `getServerSideProps` 函数。Next.js 会在每次请求页面时，在服务器上运行这个函数，获取数据并传递给页面组件。
- **实现细节**：
  - 在 `getServerSideProps` 中，通过 `context.query.id` 获取地址参数。
  - 调用后端 BFF 服务的 `/api/txs` 和 `/api/tokens` 接口。
  - 将获取到的数据作为 `props` 返回给页面组件。

<!-- end list -->

```javascript
// pages/address/[id].js
import Head from 'next/head';
import Dashboard from '../../components/Dashboard';

export async function getServerSideProps(context) {
  const address = context.query.id;

  // 调用 BFF 接口
  const [txsRes, tokensRes] = await Promise.all([
    fetch(`http://localhost:3001/api/txs?address=${address}`),
    fetch(`http://localhost:3001/api/tokens?address=${address}`),
  ]);

  const txsData = await txsRes.json();
  const tokensData = await tokensRes.json();

  return {
    props: {
      address,
      txs: txsData,
      tokens: tokensData,
    },
  };
}

function AddressPage({ address, txs, tokens }) {
  // 组件接收到 props
  return (
    <div>
      <Head>
        <title>Wallet Dashboard - {address}</title>
      </Head>
      <Dashboard address={address} txs={txs} tokens={tokens} />
    </div>
  );
}
```

#### ISR（增量静态生成）

**ISR** 适合那些数据不要求秒级更新，但又希望有很好的加载性能的页面。

- **函数**：使用 `getStaticProps` 和 `getStaticPaths`。`getStaticPaths` 告诉 Next.js 哪些路径需要预先生成 HTML，而 `getStaticProps` 则负责获取数据。
- **实现细节**：
  - **`getStaticPaths`**：如果你有已知的一些常用地址，可以在这里列出。但对于任意地址的动态路由，你可以设置 `fallback: 'blocking'`，让 Next.js 在用户访问一个未生成过的地址时，在服务器端即时生成页面并缓存起来。
  - **`getStaticProps`**：和 `getServerSideProps` 类似，但它增加了 `revalidate` 参数。`revalidate: 60` 意味着页面会每隔 60 秒检查一次数据是否有更新。

#### README 对比

在 `README.md` 中创建一个表格，清晰地对比这两种渲染方式：

| 特性             | **SSR (getServerSideProps)**     | **ISR (getStaticProps + revalidate)** |
| :--------------- | :------------------------------- | :------------------------------------ |
| **数据实时性**   | 每次请求都获取最新数据           | 周期性更新（例如：每 60 秒）          |
| **构建时间**     | 仅构建一次，页面在运行时生成     | 页面在构建时预生成，或按需生成        |
| **服务器负载**   | 每次请求都需要服务器计算         | 显著降低服务器负载，因为页面是缓存的  |
| **最佳应用场景** | 登录用户 Dashboard、实时股票行情 | 博客文章、产品列表、钱包排行榜        |

### **1.3 技术栈整合**

#### 状态管理 (Redux Toolkit)

在 Next.js 的 SSR 环境中，你需要确保 Redux 状态可以在服务器端被正确创建和序列化，然后传递给客户端进行水合（hydration）。

- **`next-redux-wrapper`**：这是一个很好的解决方案。它提供了一个 `withRedux` 高阶组件，可以轻松地将 Redux store 绑定到你的 Next.js 页面。

#### 数据获取 (Apollo Client)

如果你的项目也需要从 GraphQL API 获取数据，**Apollo Client** 依然是首选。

- **SSR 集成**：Apollo Client 也提供了 SSR 解决方案，通常需要结合 `getDataFromTree` 函数来预取数据。在 `getStaticProps` 或 `getServerSideProps` 中，你需要调用 Apollo 的方法来获取数据，并将其传递给客户端。
